## Findings checked and found NOT to be defects

* Per-endpoint limits in `routers/auth.py` use `request.client.host`, not `services/client_ip.py`. This looked like a proxy-IP bug, but the
  Dockerfile starts uvicorn with `--proxy-headers --forwarded-allow-ips "${TRUSTED_PROXIES}"`, so `request.client.host` is already the resolved client
  address in a deployed container. Only a deployment that omits those flags would share one bucket; `TRUSTED_PROXIES` must still be set (FG-167).
* Unauthenticated routes (all expected): `/`, `/health`, `/ready`, `/version`, `/auth/{check-user,send-otp,verify-otp,register,refresh,google}`,
  `/recordings/share/{token}` (token is the credential), `/admin/console` (static page; its API calls need `X-Admin-Token`). The
  `/admin/errors*` and `/admin/{stats,users,audit}` routes authenticate with the shared admin token rather than a JWT.
